# 2026-10-15 pano-stitcher 改进与验证

本轮按调研建议的六阶段顺序实施。开始时读了 AGENTS.md、README.md、指定调研报告和复跑脚本；需要 AutoStitch 实现依据时查阅本地 SIFT、束调整、渲染融合及最新核心缺口复核。未重新运行 AutoStitch EXE，没有逐像素等价或“超过 AutoStitch”的结论。

已有桌面壳、SSE、参数面板等未提交工作保留。开始时对 Git 管理和未忽略的源码做了逐文件备份、SHA256 清单及 binary diff，位置为 `output/verification-20261015/before/`。没有 reset、stash、提交或清理用户文件。`.gitignore`、前端页面、桌面壳及打包配置未被本轮改写。

## 1. 文件读写与评测

新增解耦的 `imageio.py`：文件字节→imdecode；imencode 成功后检查写入字节数，并用同目录临时文件替换目标。失败不会报告完成，原目标在替换失败时保留。中文、空格、超过传统 MAX_PATH 的路径往返通过。

CLI 汇总任一引擎的拼接/写入失败，返回 1；坏图不再静默跳过。`--report` 可保存实际后端、使用/丢弃图片索引及诊断。生成器和评测用五张固定 `view_XX.jpg` 的 SHA256 清单；旧成图、额外 JPEG 不进入该清单。变更输入哈希会被拒绝。CLI 可显式 `--manifest`，也会自动采用目录内 `inputs.json`。

普通 benchmark 遇到失败或未验证返回非零；最小 regression 即使缺深度权重，也先运行 normal/sift、lowoverlap/sift，再记录 dark/deep 未验证。成功返回码、成功编码、有限几何指标和视觉检查分别记录。

阶段验证：中文/长路径、坏解码、写失败、拼接失败、旧输出排除及普通/低重叠 SIFT 回归通过。

## 2. 内存与输出预算

`stitch_pro` 新增兼容的 `max_output_side` / `memory_mb` 参数，Web 和 CLI 将既有输出参数传入核心。`budget.py` 在 warp/remap/blender.prepare 前规划单图 ROI 和完整画布，估计输入、画布金字塔/累加器、掩码、映射及临时副本。默认画布上限 24MP、单图投影 16MP、数组估算 768MiB；超预算共同降采样，过小或异常跨度拒绝。

两块 100×100、间距 100000px 的反例得到 100100² 画布，预算依据画布而非 ROI 面积和。非有限 ROI/旋转和跨地平线的平面投影在分配前拒绝。图像与工作数组已超预算时，在 resize 前拒绝。所有输入共同使用按批次最大面积确定的工作/接缝比例，1000²+4000² 反例中每张工作图都不超过约 0.6MP。

位移场在最终合成坐标构建，接缝阶段按比例采样同一场。ROI 留出受预算约束的 26px 原尺度余量，避免小幅位移裁掉移出边缘。固定单图 ROI 的最坏情况仍受形变限幅和覆盖回退保护。

基线改用 estimateTransform/composePanorama 分离接口，按相机内参预估合成并设置 compositing resolution。混合尺寸工作/接缝分辨率也预先限制；合成比例保守处理 OpenCV 接近 1 时不实际 resize 的路径。参考 [OpenCV Stitcher 源码](https://github.com/opencv/opencv/blob/4.x/modules/stitching/src/stitcher.cpp)。本机用 OpenCV 5.0.0 实跑了普通、低重叠及混合尺寸的 480px 基线输出。

预算是保守数组估算，不是操作系统硬 RSS 限额；解释器、torch 模型缓存、所有第三方工作区及输入解码之前的内存无法由该接口严格限制。CLI 仍需先解码输入。独立进程另测实际 Windows PeakWorkingSetSize，避免将估算当实测。

## 3. 匹配与局部形变

SIFT 采用双向 ratio 互检、一对一索引及坐标去重（同一位置的不同 SIFT 方向不能重复计数）。统一 Matches 记录包含索引、分数、来源；LightGlue 适配保留模型评分，未带评分的接口明确失败。可靠图对另外检查内点空间覆盖。

局部形变不简单等同于 MAGSAC 外点：从互检后的匹配中保留幅度受限、邻域残差一致的点，使用匹配评分加权；包含可靠的非全局单应性视差。按空间网格均衡限样，并以 128 样本块累计，避免一次分配 GRID²×全部点的广播距离数组。

位移不超过原尺度 24px 或图对角线的 3%；网格位移的两个方向梯度范数和限制为 0.25，降低折叠/拉裂风险。remap 的支持要求双线性邻域有效；若有效覆盖比保守插值支持基准下降超过 2%，接缝和融合整组统一重做为全局模型。回退原因和拒绝场诊断保留。

反例验证：一致的 12px 视差被保留，注入的不一致小残差匹配被剔除；超过支持的坏场回退；大量一致 70px 样本的场被限幅、梯度受限且预测匹配残差下降。

真实山景中可信样本的**前向场预测**平均残差为 2.121→1.049px。这是匹配点上的几何预测，不是最终图像逐像素误差或视差视觉验收；该真实素材也不能代表室内近景或极端相机平移。

## 4. 连通分量与 BA

先求连通分量，按节点数最大、组内总置信度、最小索引依次选择主全景；其他组以 dropped 返回。焦距候选、生成树和 BA 全部只使用选定组。2 张置信度 3 的强组与 5 张置信度 1 的链式组反例正确选择后者。

BA 固定参考旋转；记录初始/最终 RMS、soft_l1 目标、终止状态、nfev、焦距及接受/回退原因。检查 finite、投影分母、相机后方点、SO(3)、焦距边界、目标不恶化及 RMS 容差。坏结果保留进入该阶段前的相机。status=0 不自动拒绝，status>0 也不自动接受。NaN、误差恶化和迭代上限有效解三类反例通过。

RMS 与损失尺度使用**工作图像像素**，默认逐分量 soft_l1 / f_scale=2。共享焦距适用于同焦段、共同缩放、中心裁切；任意独立 resize、不同镜头、偏心裁切仍需逐图内参。此次混合尺寸测试通过中心裁切保留同一真实焦距，而非假定任意大小图片都等价。

## 5. 合成与裁剪

曝光 feed 后，对接缝图副本 apply，再搜索 GraphCut；原低分辨率图保留用于比较。另设曝光差的普通场景中，补偿前后重叠 BGR 平均绝对差 28.08→4.14。该指标包含视差和内容差异，不单独证明色彩正确或接缝不可见。

自动裁剪将块内任何一个无效像素都保守地映射为无效，并在原分辨率验证最终框。全零掩码返回 None；融合没有支持则失败。1280² 单像素洞、奇数边长和小掩码通过，pro 返回的裁剪框有效覆盖契约为 100%。这是保守降采样网格上的内接矩形，未保证原分辨率严格最大面积。

基线从颜色估计掩码仍是近似：真实黑物体与支持外黑区无法严格区分。原图不会自动切掉所有无效外区；核心返回建议框，Web 保留用户裁剪交互。

## 6. AutoStitch 借鉴与取舍

依据本地 32 位 v2.2 Demo 静态报告，借鉴调度思想，不直接复制未经运行证明的默认数值或旧描述子/求解器。

| 项目 | 对照结果 | 决定 |
|---|---|---|
| 分阶段 BA | 树→全局的全局 RMS 基本相同；精修真实图 RMS 0.875→0.880，未显示稳定收益 | `ba_mode=staged` 仅实验；默认 single |
| 有效边缘颜色延拓 | 高对比支持边缘，零填充/近邻延拓均值 237.52/237.26，最低 235/234；无稳定改善 | 不进入生产合成；保留 tools/edge_experiment.py 与记录 |
| 顺序候选 | 5 图 10→8 候选、7 图 21→12；七图有效边仅召回 8/15，仍全部连接 | 可显式 ordered；断连全对兜底；默认 all |
| 快速融合 | 关闭局部场、2 频带、默认最长边 1600；普通/低重叠/混合/真实均成图 | 保留显式 fast；局部视差收益会减少 |

尚未实现 AutoStitch 风格的全局特征检索、多组全景返回、增量逐相机注册及雅可比稀疏求解。实验 BA 仍是逐分量 soft_l1，不是 Demo 二维径向 Huber。快速模式使用 OpenCV 降采样金字塔，不是 Demo 同尺寸递归双频带。有效支持色彩延拓没有复刻 Demo 0.5 的两轴填充公式。

## 测试矩阵与性能

Python 3.12.10、OpenCV 5.0.0、numpy 2.5.3、scipy 1.18.1，OpenCV 固定两线程和 RNG。环境纹理 seed=42，视图/暗光 seed=7，新增重复纹理 tile seed=99；每场景五张 JPEG。七张真实山景按原始证据清单逐张验证哈希，未混入旧全景。61 项独立进程实验包括前后版本、基线及选项对照；其生成器耗时不计入拼接。

| 场景 | 默认前→后耗时 | 峰值工作集前→后 | 后版本结果 |
|---|---:|---:|---|
| 普通，3 次中位数 | 2.254→2.682s（+19%） | 235.8→244.7MiB | 5/5，f=559.989px |
| 低重叠，3 次中位数 | 1.578→1.826s（+16%） | 252.4→259.4MiB | 5/5，f=561.745px |
| 混合尺寸，单次 | 1.882→2.165s（+15%） | 229.8→239.4MiB | 5/5，f=560.469px |
| 真实七图，3 次中位数 | 4.980→6.866s（+38%） | 279.6→291.0MiB | 7/7，1517×1003，真值未知 |
| 弱纹理 / 暗光 / 极端 / 重复 | 前后均拒绝 | 约 137MiB（pro） | 不算成功或质量通过 |

480px 上限的单次实测：低重叠峰值约 204.7MiB（比默认中位数低 21%），真实图 236.0MiB（低 19%），普通 216.6MiB（低 11%）。默认增加的检查、位移余量和诊断有成本，未声称本轮默认更快。

快速模式单次普通 2.06s、低重叠 1.54s、真实七图 5.48s。顺序候选真实七图单次 5.35s，但丢掉部分可靠边，不能只看速度将其设为默认。单次选项测量与三次默认中位数不是统计性速度证明。

已直接查看普通、低重叠、混合尺寸、真实山景代表成图、真实图局部关闭对照及裁剪图：成图连续，未见明显大范围拉裂；原图外部无效支持仍在，建议裁剪可去除。真实相机焦距/姿态没有真值，不把 7/7 成图当作完整几何合格。移动物体、局部近景、颜色管理、每条接缝和所有模式均未做完整视觉验收。

深度：DISK 缓存完整，LightGlue 缓存仅 `.partial`，本轮没有下载模型、运行深度匹配或将 auto/SIFT 回退计作深度成功。normal/sift 和 lowoverlap/sift 回归通过，dark/deep 未验证，整体回归按契约退出 1。弱纹理、暗光、重复纹理仍是当前 SIFT 能力缺口。

Web：本机全局 Pydantic 要求 pydantic-core=2.46.5，但安装的是 2.49.0，导入失败。在验证目录安装 2.46.5 后，使用直接 ASGI 调用验证 multipart 成图/尺寸/裁剪、坏文件 400、无匹配 422、异步任务、SSE 和结果接口通过；没有改动全局包。全局 uvicorn 启动前仍需修复其依赖。TestClient 因本机缺少 httpx2 未使用。没有浏览器、Tauri 新发布包或移动设备验证。

`--before` 和真实清单是本机证据路径，不作为跨机器固定路径；跨机器需要合法原图与新的明确清单。公开复跑可仅执行合成矩阵。生成器支持 repeat/mixed；前者为强重复纹理拒绝测试，后者为同焦距中心裁切。

本机 `output/verification-20261015/` 中：`results.json` 保存逐次输入/哈希、参数、实际后端、图像、BA/覆盖/局部场诊断及进程峰值；`summary.json` 汇总；`regression-results.json` 位于 bench 子目录；`web-verification.json` 保存 ASGI 边界；`images/` 保存成图和代表裁剪；`pilot/` 保留发现固定 ROI/支持回退问题前的试验；`before/` 是原始未提交工作快照。这些素材和备份忽略入 Git，源码复跑工具和测试保留在仓库。
